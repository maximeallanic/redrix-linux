# Haptic feedback (`haptics`)

The haptic touchpad, and a Logitech MX Master 4 mouse if one is connected, gives a short vibration when a window is
maximised, the workspace changes, the screen locks, the volume hits a limit, and on a few other GNOME events.

## Risk level: low

Everything runs in your session except one udev rule, which gives the active session write access to the
touchpad's raw HID node. Uninstalling removes all of it; your settings file is kept. Preselected in the checklist.

## Background

The Redrix touchpad (ELAN2703, HID `0018:04F3:323B` on I2C) is a standard HID haptic device (usage page Haptics,
`0x0E`). The touchpad firmware produces the click feedback on its own (Auto Trigger), and it also accepts waveforms
sent by the host: an output report with a waveform number and an intensity from 0 to 15. Its report descriptor lists
the waveforms it can play: PRESS and RELEASE, then eight Google waveforms whose roles come from ChromeOS (Chromium's
`haptic_touchpad_handler.cc`): DEEP_PRESS, DEEP_RELEASE, SNAP, SNAP_REVERSE, KNOCK, TICK, TOGGLE_ON, TOGGLE_OFF. They
are all short pulses.

Nothing on a regular Linux desktop sends those waveforms. This component adds:

- `haptic-bridge`, a small Python service on the session bus (`io.github.maximeallanic.Haptic`). It plays a waveform
  on the touchpad through its hidraw node, or on a Logitech mouse through HID++ feature `0x19B0`, using the Solaar
  package as a library. Everything about the touchpad (report number, field positions, waveform numbers) is read
  from its report descriptor, nothing is hardcoded for this model.
- `haptic-events@maximeallanic.github.io`, a GNOME Shell extension that listens to Shell signals and asks the bridge
  to play the matching event.

Only the pointing device you used last vibrates: move the mouse and events go to the mouse, touch the touchpad and
they go to the touchpad. Events generated by the compositor itself (synthetic events, the logical pointer during a
window drag) do not change the active device.

## What the installer changes

| Path | Content |
|---|---|
| `/etc/udev/rules.d/70-haptic-touchpad.rules` | `TAG+="uaccess"` on the hidraw node of `0018:04F3:323B`: the user of the active session may write to it |
| `~/.local/bin/haptic-bridge` | the bridge (service and command-line tool) |
| `~/.local/lib/haptic-bridge/haptic_touchpad.py` | the touchpad module (descriptor parsing, output report) |
| `~/.config/systemd/user/haptic-bridge.service` | user service, enabled and started |
| `~/.config/haptic-bridge/events.toml` | your settings: copied when absent; on a reinstall only the events it lacks are added, after a dated copy |
| `~/.config/autostart/solaar.desktop` | `Hidden=true`, only if you had no such file: Solaar's tray app would be a second HID++ client of the mouse |
| `~/.local/share/gnome-shell/extensions/haptic-events@maximeallanic.github.io` | the Shell extension, enabled |

Debian packages: `solaar`, `python3-gi`, `python3-tomlkit`. Solaar's own udev rule (`60-solaar.rules`, from the
package) is what gives the session access to Logitech receivers and mice.

Trade-off of the udev rule: any process of your session can also read the touchpad's raw reports. That is the same
compromise Solaar makes for Logitech devices.

## Events

`~/.config/haptic-bridge/events.toml` maps each event to a mouse waveform (`wave`), a touchpad waveform (`touchpad`)
and a minimum delay between two plays (`cooldown_ms`). Both waveforms are optional.

| Event | When | Mouse | Touchpad |
|---|---|---|---|
| `edge` | a window is maximised in one direction only (tiled to a side) | SHARP_COLLISION | KNOCK |
| `maximize` | a window is maximised or goes fullscreen | DAMP_STATE_CHANGE | SNAP |
| `unmaximize` | a window leaves maximised or fullscreen | SHARP_STATE_CHANGE | SNAP_REVERSE |
| `workspace` | the active workspace changes | SHARP_STATE_CHANGE | TICK |
| `overview` | the overview opens or closes | DAMP_COLLISION | TICK |
| `lock` | the screen locks | COMPLETED | TOGGLE_OFF |
| `screenshot` | a screenshot is taken | KNOCK | KNOCK |
| `button` | an extra mouse button (back, forward, others) is pressed | SUBTLE_COLLISION | none |
| `volume` | the volume changes | SUBTLE_COLLISION | TICK |
| `volume-stop` | the volume reaches 0 or its maximum | DAMP_COLLISION | KNOCK |
| `toggle-on` | you switch on a quick-settings tile or a menu switch | SHARP_STATE_CHANGE | TOGGLE_ON |
| `toggle-off` | you switch one off | DAMP_STATE_CHANGE | TOGGLE_OFF |

Toggles only vibrate when you flip them: a state that changes on its own (Wi-Fi reconnecting) plays nothing. In the
overview, the mouse's back and forward buttons also switch workspaces.

Global settings at the top of the file:

- `force`: mouse intensity, 0 (off) to 100.
- `touchpad_force`: touchpad intensity, 0 (off) to 100, scaled to the touchpad's 0-15 (any non-zero value is at
  least 1).

To silence one event, keep its line and add `force = 0` to it. Do not delete the line: the installer adds every
event the file lacks, so a deleted line comes back at the next install. To keep the mouse and silence the touchpad
for one event, remove `touchpad` from its line. After editing:

```sh
systemctl --user restart haptic-bridge.service
```

Mouse waveforms are the 16 of Solaar's `HapticWaveForms`; each mouse announces the ones it supports (the MX Master 4
tested announces 15, not WHISPER_COLLISION). A waveform the connected mouse does not offer is skipped for the mouse
only, with one warning in the journal.

## Command line

```sh
haptic-bridge --touchpad                 # the touchpad's hidraw node and the waveforms it offers
haptic-bridge play maximize              # play an event on the active device
haptic-bridge play edge touchpad         # on a given device (mouse|touchpad); exit status 1 if nothing played
haptic-bridge --ping                     # is a haptic Logitech mouse connected?
haptic-bridge --list                     # the waveforms the mouse announces
```

## Mouse (optional)

A Logitech mouse with a haptic motor (tested: MX Master 4 on a Logi Bolt receiver) is found through Solaar's
library: the first device whose feature list contains `0x19B0`. Without one, only the touchpad vibrates and the
verify step reports it as information, not as a failure. If the mouse sleeps or disconnects, events are dropped
silently (one journal line) and the bridge looks for it again at most every 10 seconds.

## Requirements

- The ELAN2703 haptic touchpad of the Redrix.
- GNOME Shell 50 or 51 (the extension declares those versions).
- A Logitech haptic mouse is optional.

## Verify

```sh
./verify.sh haptics
```

| Check | Meaning |
|---|---|
| `haptic-bridge.service is running` | the user service is active |
| `udev rule for the touchpad` | the rule in `/etc/udev/rules.d` is the kit's |
| `haptic touchpad found: /dev/hidrawN` | the bridge found a hidraw node with a haptic Manual Trigger and a waveform list |
| `your session can write to /dev/hidrawN` | the uaccess ACL is in place (granted to the active session: log out and back in after installing) |
| `events.toml has every event of the kit` | your file is valid TOML and lacks none of the kit's events |
| `Logitech haptic mouse connected` | shown as INFO when there is none: optional |
| `extension files up to date` / `extension running` | the installed extension matches the kit and GNOME reports it ACTIVE |
| `test vibration played on the touchpad` | the bridge played `lock` on the touchpad: rest a finger on it to feel it |

## Uninstall

```sh
./uninstall.sh haptics
```

This disables and removes the extension, the service and the bridge, removes the Solaar autostart entry only if it
is still the one the kit wrote, and removes the udev rule. Kept: `~/.config/haptic-bridge/events.toml` and the
`solaar` package (remove it with apt if you do not use it).

By hand:

```sh
sudo rm /etc/udev/rules.d/70-haptic-touchpad.rules && sudo udevadm control --reload-rules
systemctl --user disable --now haptic-bridge.service
rm ~/.local/bin/haptic-bridge ~/.config/systemd/user/haptic-bridge.service
rm -r ~/.local/lib/haptic-bridge
gnome-extensions disable haptic-events@maximeallanic.github.io
rm -r ~/.local/share/gnome-shell/extensions/haptic-events@maximeallanic.github.io
```

## Known limitations

- The strength of the physical click itself (PRESS/RELEASE produced by the touchpad) cannot be changed. It is only
  adjustable when the host drives the click, which needs `CONFIG_HID_HAPTIC` (Linux 6.18, `hid-multitouch`); Debian's
  kernel does not enable it, so it would take a rebuilt kernel.
- The touchpad only offers short pulses: there is no touchpad equivalent to the mouse's long patterns (alerts,
  JINGLE).
- `overview` is one event for both opening and closing.
- `button` exists only for the mouse; it is silent while the touchpad is the active device.
- Only buttons that the kernel exposes as mouse buttons reach the Shell. The MX Master 4's gesture button, thumb
  wheel and haptic sense panel keep their factory behaviour.
- The bridge does not show the mouse battery: on the machine tested, the kernel attached no HID++ driver to the Bolt
  receiver, so UPower does not see it either.
