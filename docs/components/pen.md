# Pen support (`pen`)

The built-in pen stays on the laptop screen when a monitor is plugged in, appears in Settings > Wacom Tablet, and
shows a small dot under its tip instead of the mouse arrow.

## Risk level: low

Two description files for libwacom and a GNOME Shell extension. Nothing about input handling in the kernel changes.
Preselected in the checklist.

## Background

The touchscreen and pen digitiser is an ELAN controller (ACPI `ELAN2513`, HID product `04f3:2f75`). The kernel
already drives it (`hid-multitouch`): hover, touch and pressure work out of the box. The tested USI pen reported 38
distinct pressure levels and no tilt.

Two things are missing on a stock install:

1. **libwacom does not know product `2f75`.** libwacom 2.20 has `elan-2513.tablet`, but not this product. Without a
   description, GNOME does not know the digitiser is built into the laptop display: there is no Tablet section in
   Settings, and once an external monitor is attached the pen can be mapped over the whole desktop. The kit adds
   `elan-2f75.tablet` (integrated in display and system, 285 x 189 mm, measured from the evdev axes: X 0-17940 at
   63 units/mm, Y 0-11180 at 59 units/mm).
2. **The pen has no buttons and no eraser**, but the controller advertises `BTN_TOOL_RUBBER`, `BTN_STYLUS` and
   `BTN_STYLUS2`. Only `BTN_TOOL_PEN` and `BTN_TOUCH` ever fire. libwacom's generic styli all declare two buttons,
   so GNOME would offer mappings for buttons that do not exist. `redrix-pen.stylus` describes a one-tip pen with
   pressure only (ID `0x0:0xffff0`, group `redrix-pen`), just below libwacom's own generic range.

Under Wayland, Mutter draws a cursor under the pen tip: the theme's arrow, or whatever the application asks for. No
setting hides it, and `Meta.CursorTracker.inhibit_cursor_visibility()` only applies to the mouse pointer. The
extension `pen-dot@maximeallanic.github.io` answers Mutter's `Meta.Backend::override-cursor` hook with "no cursor"
while the pen is the pointing device in use, and draws a 6 px dot at the tip instead.

## What the installer changes

| Path | Content |
|---|---|
| `/etc/libwacom/elan-2f75.tablet` | the digitiser description (`DeviceMatch=i2c\|04f3\|2f75`, `IntegratedIn=Display;System`) |
| `/etc/libwacom/redrix-pen.stylus` | the pen description (no button, no eraser, pressure) |
| libwacom's generated udev rules and hwdb | regenerated by `libwacom-update-db`, then udev reloads the input devices |
| `~/.local/share/gnome-shell/extensions/pen-dot@maximeallanic.github.io` | the Shell extension, enabled |

Debian package: `libwacom-bin` (provides `libwacom-update-db` and `libwacom-list-local-devices`).

Mutter reads libwacom when the device is (re)connected: log out and back in after installing.

## Requirements

- The Redrix built-in digitiser (`04f3:2f75`).
- GNOME Shell 50 or 51 for the extension.

## Verify

```sh
./verify.sh pen
```

| Check | Meaning |
|---|---|
| `pen digitiser described to libwacom` | `/etc/libwacom/elan-2f75.tablet` is the kit's |
| `pen profile installed` | `/etc/libwacom/redrix-pen.stylus` is the kit's |
| `libwacom recognises the built-in pen digitiser (04f3:2f75)` | `libwacom-list-local-devices` lists the digitiser |
| `pen described without button nor eraser (Redrix Pen)` | the same listing uses the kit's pen description |
| `extension files up to date` / `extension running` | the extension matches the kit and GNOME reports it ACTIVE |
| `pen-dot: Mutter consults its cursor hook` | the extension logged, this session, that its hook is installed |

Output of the libwacom checks on a tested machine:

```
  [ OK ] pen digitiser described to libwacom
  [ OK ] pen profile installed
  [ OK ] libwacom recognises the built-in pen digitiser (04f3:2f75)
  [ OK ] pen described without button nor eraser (Redrix Pen)
```

The extension writes at most three diagnostic lines per session:

```sh
journalctl --user -b -o cat | grep 'pen-dot:'
```

`enabled ...` (hook installed; `pen-dot: error: ...` when Mutter does not consult it), `first stylus event ...`
(pen events reach the Shell) and `first cursor hidden ...` (Mutter asked the hook for the pen).

## Uninstall

```sh
./uninstall.sh pen
```

By hand:

```sh
sudo rm /etc/libwacom/elan-2f75.tablet /etc/libwacom/redrix-pen.stylus && sudo libwacom-update-db
gnome-extensions disable pen-dot@maximeallanic.github.io
rm -r ~/.local/share/gnome-shell/extensions/pen-dot@maximeallanic.github.io
```

## Known limitations

- Applications that give the pen a cursor *image* of their own (through `zwp_tablet_tool_v2.set_cursor` with a
  surface: GTK 3 applications, anything under XWayland) keep that cursor next to the dot. Mutter has no hook for
  that case. Applications that ask for a cursor *shape* (`cursor-shape-v1`: GTK 4, the Shell, recent browsers) show
  the dot alone.
- No tilt: the digitiser does not report it.
- The pen does not work inside Android containers such as Waydroid, which do not forward Wayland tablet events
  (observed during testing; not something this kit changes).
- Upstream: the right long-term fix for the description files is to send them to
  [libwacom](https://github.com/linuxwacom/libwacom). That has not been done yet.
